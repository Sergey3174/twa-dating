# TWA Dating

Мобильное приложение знакомств 18+ в Telegram. Тёмная тема Fragment сохранена; DESIGN.md описывает интерфейс TWA Dating.

## Запуск

- `npm install`
- `npm run dev`
- `npm run build` — production в build/
- `npm run lint`

## Возможности

Свайп вправо отправляет лайк, влево пропускает анкету. Действия дублируются кнопками. Нажатие на фото открывает анкету и текстовую ленту человека. Нижнее меню: знакомства, мои лайки, взаимно, профиль. Лайки можно удалять. Взаимность определяется входящим лайком в демо-данных.

Профиль: имя, возраст 18–99, город, пол, цель знакомства, описание, интересы и Telegram. Фильтры отдельной модальной панелью: возраст, расстояние, пол, цель. Пустая подборка позволяет изменить фильтры или вернуть пропущенные анкеты.

## Данные и API

src/dating/api.ts — типизированный асинхронный mock API. Все изменения идут через адаптер, сохраняются в localStorage под ключом twa-dating-v1. Сервер и авторизация не подключены. Фотографии загружаются с Unsplash и требуют сети.

Демо-контакты не являются реальными Telegram-аккаунтами: кнопка «Написать в ТГ» открывает выбор получателя. Для production API должен возвращать контакт только после взаимного лайка; заменить share-ссылку на ссылку этого контакта.

План HTTP API: GET /me, PATCH /me, GET /profiles (фильтры и пагинация), POST /swipes, GET /likes, GET /matches. Сервер должен проверять Telegram initData, возраст, права доступа к контактам и взаимность. Подборка пока из шести статичных анкет, расстояния демонстрационные.


## Структура приложения

- `src/dating/App.tsx` — подключение провайдера и роутера.
- `router.tsx` — React Router: `/`, `/likes`, `/matches`, `/profile`, `/people/:id`; неизвестные адреса перенаправляются на главную.
- `layout/` — AppLayout с Outlet, AppHeader, BottomNav и конфигурация навигации.
- `pages/` — DiscoverPage, LikesPage, MatchesPage, ProfilePage, PersonPage.
- `components/cards/` — SwipeProfileCard, PersonCard и MatchRow. Свайп большой анкеты и свайп строки взаимности имеют локальное состояние.
- `components/` — FilterSheet и EmptyState.
- `state/` — DatingProvider и useDating: загрузка данных, состояние, операции mock API, уведомления и блокировка повторных запросов.
- `telegram.ts` — переход в Telegram; `api.ts` — типы и mock API.

Карточки из списков открываются по адресу `/people/:id`. Возврат из анкеты ведёт в исходный раздел, прямое открытие — на главную. Смена маршрута и следующая анкета сбрасывают прокрутку. Сервер должен возвращать index.html для клиентских маршрутов (настройки nginx и Vercel уже содержат fallback).

## Профиль и настройки

`/profile` — главный экран профиля: аватар, имя, заполненность, переход к собственной анкете и редактированию. Премиум и платные предложения отсутствуют. Шестерёнка открывает `/settings`: тип знакомства, видимость, пауза, инкогнито, автовоспроизведение, уведомления и демонстрационный город. Настройки сохраняются через mock API в localStorage; пока не изменяют выдачу и не отправляют уведомления.

`/profile/me` — собственная анкета на базе SwipeProfileCard: фото между шапкой и меню, ниже сохранённые сведения о себе. Свайпы и лайки себе отключены. Фото демонстрационное; имя, возраст, описание, город, цель и интересы берутся из сохранённого профиля. `/profile/edit` — прежняя форма редактирования.

## Редактор профиля: фото и интересы

В `/profile/edit` добавлены сетка из шести фотографий, заполненность профиля, интересы (до 5), один любимый интерес, ценности/сообщества и качества (до 3 каждого). Выбор происходит в модальных панелях с черновиком и отменой; весь профиль сохраняется основной кнопкой формы.

PhotoEditor принимает JPG/PNG/WebP до 15 МБ, уменьшает длинную сторону до 1000 px и сохраняет JPEG в mock localStorage. Фото можно удалить, поменять местами стрелками или перетаскиванием на компьютере. Первое фото — главное и аватар; остальные доступны в собственной анкете. При превышении квоты браузера сохранение выдаёт ошибку, серверного хранения пока нет. Старые профили без новых полей продолжают работать. Видео и реальная верификация не подключены.

Дополнительные поля профиля (работа, образование, родной город, рост, спорт, привычки, планы на детей) редактируются строками в ProfileDetails / DetailFieldSheet и сохраняются общей кнопкой профиля. Незаполненные необязательные поля не выводятся в своей анкете.

ProfileContent объединяет представление анкет: чипы характеристик, цель, качества, любимый интерес, сообщества и дополнительные фото между секциями. Используется на главной, в чужом профиле и предпросмотре своей анкеты; отсутствующие значения скрываются.

## Общая структура профиля и фильтров

`profileSchema.ts` содержит единые варианты пола, цели знакомства, планов на детей, наличия детей, религии и языков, а также границы возраста и роста. И редактор, и поиск используют эти справочники. Тип Person получает языки, религию и подтверждённость из Profile; преобразование собственной анкеты сохраняет их.

В редактор добавлены языки (множественный выбор), необязательная религия и явно обозначенный демо-статус подтверждённости. В анкете отображаются заполненные языки, религия и подтверждение. Настоящий статус проверки должен задавать сервер, а не пользователь; переключатель предназначен только для текущих моков. Расстояние — вычисляемый атрибут подборки, город редактируется в профиле.
